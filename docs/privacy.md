# SYNK Privacy & Data Handling

Research prototype — not for clinical diagnosis or treatment.

## Principles

1. **Synthetic by default.** All demo, CI and UI-serving data is generated by the synthetic
   generator and labelled as synthetic everywhere it appears.
2. **No restricted data in the repo.** MIMIC-IV/eICU or institutional extracts must be obtained under
   the source's own licence/credentialing; SYNK provides adapter *interfaces* only and never
   downloads, redistributes or commits such data.
3. **Secrets via environment only.** Credentials live in `.env` (git-ignored) or the environment;
   `.env.example` documents every variable without real values. No API keys are required for any
   core functionality — models run locally.
4. **Minimal persistence.** The database stores identifiers, derived predictions and metrics. Raw
   note text is persisted only for the synthetic demo corpus; for real datasets, keep notes in the
   authorised store and point SYNK's adapters at it rather than copying into the demo DB.
5. **Log hygiene.** Clinical note text is never written to logs; the JSON logging helpers are
   intended for identifiers and metrics only.

## Operational requirements when using real data

- Execute locally or inside an approved environment; do not enable external telemetry.
- Disable the demo engine and point `data` paths at the authorised store.
- Keep `text_deid: true` (dates/long numbers redacted) unless downstream requirements say otherwise.
- Review `docs/model_card.md` out-of-scope uses before any evaluation on real records.

## .gitignore guarantees

`data/`, `artifacts/`, `*.db`, `.env` and virtual environments are excluded from version control by
default (`.gitignore`); only directory placeholders are tracked.
